# spx-exception-handling

GAS WebApp xử lý ngoại lệ (mất bill SPX): tạo mã Box/Item nội bộ, lưu ảnh Drive, Resolve bill, Thanh Lý theo lô, in QR, quét camera + súng.

Workflows giống repo `spx-diem-danh`:
- `.github/workflows/deploy.yml` — push `main` → `clasp push` + tạo version + redeploy production `/exec` (cần secrets `GAS_SCRIPT_ID`, `CLASPRC_JSON`).
- `.github/workflows/test.yml` — CI gate: `npm test` + Python `unittest` + `build:local` + `test:chrome`.

## Setup sau khi tạo repo

1. Vào repo Settings → Secrets and variables → Actions → New repository secret:
   - `GAS_SCRIPT_ID` = ID Apps Script project (đã set sẵn khi tạo repo).
   - `CLASPRC_JSON` = nội dung `~/.clasprc.json` (copy từ máy đã `clasp login`, hoặc từ repo cũ).
2. Push lên `main` → kiểm tra tab Actions (Deploy + Test chạy).
3. Mở Apps Script project → Deploy → kiểm tra `/exec` đã lên version mới.

## Setup GAS (Script Properties)

- `SPREADSHEET_ID` = ID Spreadsheet DB (không hardcode — luật 1). Sheet tự tạo: `Items` (12 cột theo `docs/db-schema.md`), `Photos`, `ActivityLog`, `PrintedCodes` (giữ chỗ mã in hàng loạt), `Feedback` + `FeedbackReplies` (nhóm chat góp ý chung).
- `FOLDER_ID` = ID thư mục Drive chứa ảnh (server tạo subfolder `YYYY-MM`). Lấy từ URL folder `drive.google.com/drive/folders/<ID>`, điền vào Script Properties, không hardcode/không gửi qua chat.
- `FOLDER_ID_HN` = ID folder MatBillHNSOC (ảnh kho HN SOC, cấu trúc `YYYY-MM` như folder gốc — user tự tạo folder, chỉ điền ID vào Script Properties, không hardcode).
- `ADMIN_EMAILS` = email ADMIN seed, cách nhau dấu phẩy (khi sheet `Users` còn trống thì các email này là ADMIN, còn lại STAFF; có ADMIN rồi thì phân quyền tiếp ở trang Quyền Truy Cập).
- Bảng `Users` có 5 cột `email role added_at added_by perms` (`perms` = key phân tách phẩy; trống = mặc định role, `NONE` = tắt hết, ADMIN bỏ trống = 15/15; xem mockup `mockups/06-m6-role-tich-quyen-theo-tung-nguoi-dung.html`).
- 15 key quyền (`PERM_KEYS` SSOT `Code.gs`/`index.html`/`mock/mock-google.js`/`api/logic.py`): mặc định STAFF BẬT `create resolve liq print siteHN siteHN2 dash backlog note feedback`, TẮT `editStatus editPhotos adminReply roleView roleManage`; `checkPerm_(key)` chặn mọi RPC ghi (`siteHN/siteHN2/dash` là quyền UI-only: phân kho ở menu + ẩn tab Dashboard, không thêm gate server vì Dashboard tính client-side và Users theo từng kho), `requireAdmin_()` chỉ giữ cho `fixPhotoSharing/auditPhotosOutsideFolder/diagIdentity`. Bảng Role dùng công tắc bật/tắt, legend chỉ hiện Tên đầy đủ; nhãn tài khoản hiện tại là `Bạn`. STAFF cũ có chuỗi `perms` lưu thiếu 3 key mới sẽ bị TẮT 3 quyền này — ADMIN bật lại ở tab Role.
- Sau khi đổi `appsscript.json` (vd thêm `oauthScopes`): mở editor bằng email deploy → Run 1 hàm bất kỳ → duyệt màn hình Review permissions (phải thấy Drive + email) → deploy/update deployment đang phục vụ. CI không thể consent thay (non-interactive) nên bước tay này bắt buộc đúng 1 lần.

## Contract

- Mã mới: `Box.DD-MM-YYYY.seq` / `Item.DD-MM-YYYY.seq` (seq/ngày từ 1, server cấp trong lock). Mã cũ `BOX.DDMMYYYY.NN` vẫn đọc được.
- Trạng thái canonical: `chua_xu_ly` (hiển thị Lưu kho) · `da_tim_bill` (hiển thị Resolve) · `thanh_ly` (hiển thị Thanh Lý) + `da_cho_di`/`tieu_huy` (import cũ). Map SSOT tại `scripts/import-csv.js:STATUS_RULES`, mirror `api/logic.py` + `Code.gs`.
- API (`google.script.run`): `listItems(limit, offset)/listFull(limit, offset)` — phân trang 150/trang từ đầu (mới nhất), cuộn tới cuối tự tải tiếp, cache dồn theo `code` · `listFull(limit — tối đa 150, batch 1 lần: Items + Photos + ActivityLog, trả [{item (kèm extras/slots ảnh đầy đủ), history}])` · `getItem(code)` (kèm history Chi tiết trạng thái — mốc chuyển trạng thái có `bill` + `extras`/`slots` ảnh) · `previewCode(kind)` (nhảy qua mã đã giữ chỗ in) · `previewBulkCodes(kind, count)` (sinh dãy liên tục, `count` chặn 1–10, append giữ chỗ vào `PrintedCodes` trong lock) · `createBox(p)` · `createItem(p)` (`p={description, note, outer, product, extras[], customCode?}` (mã ghi đè từ nút Sửa/Ok — đúng dạng `Box./Item.` khớp loại, trùng thì server báo lỗi), trả thêm `item` để client unshift cache không reload) — Box bắt buộc ngoại quan + sản phẩm, Item bắt buộc 1 ảnh sản phẩm, ảnh 3 tùy chọn · `enqueuePrintJob(codes[])/pollPrintJobs()/claimPrintJob(job_id, stationId)/ackPrintJob(job_id, ok, note)` (hàng in `PrintQueue`: phone gửi, trạm laptop poll 3s + lock claim, serial + nghỉ 10s) · `resolveItem(code, bill)` · `liquidateBatch(codes[], liqCode)` · `listFeedback()` · `addFeedback(text)` · `replyFeedback(id, text)` (nhóm chat góp ý chung, riêng biệt Chi tiết đơn — mỗi tin hiện email + thời gian; ## Hai kho HN2/HN (station selector)

- Dropdown station ngay dưới logo (header + sidebar, 2 option, không ô search): `HN2 SOC` (mặc định) · `HN SOC`. Đổi kho → xóa cache list/ảnh/lô chưa gửi → tải lại → toast `Đã chuyển sang …`. Giao diện 2 kho giống hệt nhau, chỉ dữ liệu phân chia.
- HN2 đọc/ghi sheet tên gốc; HN đọc/ghi tên gốc + đuôi `HNSOC` (`ItemsHNSOC`, `PhotosHNSOC`, `ActivityLogHNSOC`, `PrintedCodesHNSOC`, `PrintQueueHNSOC`, `FeedbackHNSOC`, `FeedbackRepliesHNSOC`, `BacklogHNSOC`, `UsersHNSOC`). Sheet `*HNSOC` tự tạo khi gọi lần đầu (trừ `BacklogHNSOC` thiếu thì server báo để paste tay vì là sheet import read-only).
- `UsersHNSOC` trống thì tự seed từ `ADMIN_EMAILS` — phải phân quyền lại bên HN. Ảnh 2 kho nằm 2 cây Drive riêng (`FOLDER_ID` vs `FOLDER_ID_HN`, subfolder `YYYY-MM`); đứng kho nào thì server từ chối ảnh kho kia. Muốn kín tuyệt đối thì share mỗi folder đúng nhóm kho.
- Contract: mọi RPC đọc/ghi theo sheet nhận thêm `site` cuối args (`'HN2'`/`'HN'`; lạ/trống → `'HN2'`), kể cả API ảnh (`getPhoto`/`getThumb`/`getThumbs`).

## Sự cố ảnh (tự kiểm tra, không cần code)

- Hộp ảnh lỗi ghi `· [loại] · rev`: `[drive]` = thumbnail Drive, `[tem]` = URL googleusercontent (không tách được Drive ID), `[blob]` = blob cache hỏng (app tự trục xuất + tải lại qua server), `[appsheet]/[link]` = URL lưu trong sheet không phải Drive (phải dọn dữ liệu). Rev (`r…`) xác nhận máy đang chạy bản build nào — test `/dev` thì thêm `?v=2` vào URL để ép tải mới qua cache Safari.
- Tab Role → Sửa share ảnh cũ: `không đọc được` = ID rác/thiếu quyền đọc; `bị chặn share` = thiếu quyền đổi share; `chưa rõ chủ (deploy trống)` = `Session.getEffectiveUser()` không trả email (thường gặp trên URL `/dev`); đối chiếu dòng `Deploy:` cạnh email đăng nhập — deploy khác chủ file thì share luôn Access denied. Nút Chẩn đoán danh tính đọc active/effective/chủ file đầu/share hiện tại (chỉ đọc, không đổi gì) để phân biệt URL nào danh tính nào khi có nhiều deployment cùng Active.
- Server đọc được file nhưng browser không thấy: Safari chặn cookie third-party trong iframe (Cài đặt → Safari → Tắt Ngăn theo dõi chéo trang web để kiểm chứng, không dùng làm cách sửa) — đường base64 qua `google.script.run` (`getPhoto`) miễn nhiễm vì chạy bằng quyền deployer.
- Quan sát server không cần deploy: tab Executions trong Apps Script editor (lỗi + duration từng run), hoặc chạy `me()`/`fixPhotoSharing()` thẳng trong editor (chạy bằng chính bạn — share được ở đây mà webapp không được thì chắc chắn do danh tính deploy).

## Đo timing GAS từ local

- Token: OAuth Playground → chọn Apps Script API v1, scope `script.processes` → Authorize → copy access token (hết hạn ~1h).
- Chạy (secret chỉ qua env, không commit): `GAS_SCRIPT_ID=<id> GAS_MEASURE_TOKEN=<token> npm run measure:gas -- --limit 20 --fn listFull`
- Cách đối chiếu: thao tác trên app (mở trang/create/resolve) → chạy lệnh → đọc `duration` từng execution + tổng hợp avg/max.
- Không setup: tab Executions trong Apps Script editor cũng hiện duration từng run.
